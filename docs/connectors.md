# Коннекторы Johnny

**Коннектор** — это доступ к внешней тулзе (платный API, локальный пакет, свой
сервис) из голосовой команды. Общий слой в `johnny/connectors/` берёт на себя
всё, что у таких вызовов одинаково: согласие, кеш, суточную квоту, cooldown и
честный отказ вместо падения.

## Зачем общий слой

План привязывает к каждой внешней тулзе один и тот же набор требований:
rate-limit, кеширование, офлайн-режим, приватность и согласие. Тулз в плане
четырнадцать. Если каждая реализует это сама, то любая ошибка в политике
исправляется четырнадцать раз — а найдётся она в одной.

Поэтому наследник описывает **только своё**: как проверить готовность
(`available`) и как сделать вызов (`_run`). Политика живёт в `base.py` и уже
проверена тестами.

## Архитектура слоёв

```
Фраза пользователя
       │
       ▼
  router.py                 — commands.yaml → RoutedAction
       │
       ▼
  actions/connector_action  — вытащить аргумент из фразы (ссылка, путь, ник)
       │
       ▼
  connectors/factory.py     — собрать коннектор из config (ключи, согласие)
       │
       ▼
  connectors/base.py        — согласие, кеш, готовность, cooldown, квота
       │
       ▼
  connectors/<tool>.py      — собственно запрос к сервису
       │
       ▼
  connectors/store.py       — кеш ответов с TTL и счётчики квоты на диске
```

## Порядок проверок в `call()`

Порядок выбран сознательно и менять его нельзя не подумав — он и есть контракт:

| № | Проверка | Почему именно здесь |
|---|----------|---------------------|
| 1 | согласие | До всего остального: без согласия сервис не должен узнать даже о факте запроса |
| 2 | кеш | **До** готовности и cooldown — это и есть офлайн-режим: сервис лёг, ключ отобрали, а вчерашний ответ под рукой |
| 3 | готовность | Нет ключа или пакета — отказ с причиной, а не «не понял» |
| 4 | cooldown | Сервис только что не ответил, не ждём таймаут повторно |
| 5 | квота и интервал | Суточный лимит по тарифу; интервал выжидаем сами, не ловим 429 |
| 6 | вызов | Исключение → `mark_failure` + `warn_once` + отказ, наружу оно не летит |

Счётчик квоты растёт в `finally`: неудачный запрос у большинства сервисов тоже
списывается, и не учесть его — значит перерасходовать лимит.

## Быстрый старт: свой коннектор

```python
from .base import Connector


class MyToolConnector(Connector):
    name = "mytool"
    requires_consent = False      # True для всего, что касается людей
    ttl_seconds = 86400.0
    daily_quota = 100             # цифра своего тарифа, не «на глаз»
    min_interval_seconds = 1.0

    def __init__(self, *, api_key="", daily_quota=None, **kwargs):
        super().__init__(**kwargs)
        self._api_key = str(api_key or "")
        if daily_quota is not None:
            self.daily_quota = int(daily_quota)

    def available(self):
        if not self._api_key:
            return False, "Для mytool нужен ключ в secrets.yaml"
        return True, ""

    def _run(self, **params) -> dict:
        response = post(API_URL, headers=..., json=params, timeout=20)
        if response.status_code != 200:
            raise RuntimeError(f"HTTP {response.status_code}")
        return self._compact(response.json())

    def describe(self, data: dict) -> str:
        return f"Нашёл совпадений: {data['total']}"
```

Дальше три шага, и команда доступна голосом:

1. `connectors/factory.py` → строка в `BUILDERS`: имя → класс и карта «аргумент
   конструктора → ключ в secrets.yaml»: `"mytool": (MyToolConnector, {"api_key": "mytool_api_key"})`.
   Карта, а не одна строка, потому что у некоторых сервисов доступ — пара
   (Face++: ключ **и** секрет), и особый случай в фабрике под неё писать не надо.
2. `actions/connector_action.py` → обработчик, который достаёт аргумент из фразы.
3. `config/commands.yaml` → фразы. **Выше** хвостового блока `открой *` / `фокус *`:
   `route_exact` берёт первое совпадение по порядку файла, и жадный шаблон
   заберёт фразу себе.

## Что писать в каждом методе

### `available() -> (bool, str)`

Причина отказа **уходит человеку в ответ и в лог**. Значит: по-русски, без
внутренних деталей и без ключей ни при каком раскладе — это проверяется тестом
(`test_key_never_leaks_into_refusal_text`).

### `_run(**params) -> dict`

Бросать исключение при неудаче — `call()` сам переведёт его в отказ, отметит
cooldown и напишет в лог один раз. Возвращать **сжатые** данные, а не сырой
ответ сервиса: в кеш попадает именно этот словарь, и всё лишнее в нём будет
лежать на диске неделю.

Текст ошибки попадает в лог. Тело ответа в него включать нельзя, если сервис
эхом возвращает запрос: LibreTranslate так возвращает и `api_key`, поэтому
`translator.py` поднимает `RuntimeError(f"HTTP {code}")` без тела. Где эха нет —
включать стоит: у Azure самая частая ошибка «feature Caption is not supported in
this region», и по одному коду её не опознать.

Учитывать надо и обратное направление: у Face++ ключ и секрет уходят **полями
формы**, а не в строке запроса, потому что строку запроса пишет в свой лог любой
прокси по пути.

### `describe(data) -> str`

Ответ голосом. Одно-два предложения: список из двадцати доменов вслух
бесполезен.

### `cache_params(params) -> dict`

Какие параметры образуют ключ кеша. По умолчанию — все, переопределять только
там, где параметр **не описывает запрос однозначно**.

Живой пример — путь к файлу: `screenshot.png` перезаписывается каждым новым
снимком, и ключ по пути отдал бы вчерашний ответ про **другого человека**.
Поэтому `azure_vision.py` и `faceplusplus.py` ключуются хешем содержимого, а путь
в ключ не идёт.

Второй пример из той же пары — параметры вызова: у `azure-vision` в ключ входят
`features`, потому что «прочитай текст» и «что на картинке» — два разных ответа
на одну и ту же картинку, а общий ключ отдавал бы один вместо другого.

## Приватность

Требование плана держится механикой, а не обещанием:

- `requires_consent = True` — ни одного сетевого запроса без согласия; тест
  проверяет, что при отказе на диск не пишется вообще ничего.
- Согласие живёт в `settings.yaml`, **не** в наличии ключа: ключ значит «могу»,
  согласие — «разрешено». Оплата ключа сама по себе поиск по лицам не включает.
- Точечное согласие сильнее общего — «всё, кроме поиска по лицам» включается
  одной строкой, иначе человек выключает целиком и не пользуется ничем.
- Признаки лица режутся до записи в кеш: 83 точки разметки на лицо от Face++
  голосу не нужны, а на диске это биометрия чужого человека, лежащая неделю.
- Пол (`gender`) у Face++ **не запрашивается вовсе**. Сервис отдаёт его как
  выбор из двух, ни одной нашей команде он не нужен, а ошибка в нём — ошибка про
  живого человека. Тест проверяет и что его нет в запросе, и что он не просочился
  в ответ, если сервис пришлёт его сам.
- Обращения к разбору лиц и к OSINT пишутся в журнал доступа рядом с кешем: он
  отвечает на вопрос «чьи лица и когда мы отправляли». В журнале только имя
  файла, короткий хеш и число лиц — ни снимка, ни признаков.

## Настройка

`config/secrets.yaml` — только ключи (файл в `.gitignore`, образец —
`secrets.yaml.example`):

```yaml
azure_vision_key: ""
faceplusplus_api_key: ""
faceplusplus_api_secret: ""   # доступ к Face++ — пара; забывают обычно вторую строку
```

`config/settings.yaml` — что разрешено и по какому тарифу:

```yaml
connectors:
  consent: true               # общее согласие на внешние запросы
  azure-vision:
    # ОБЯЗАТЕЛЬНО: у каждого ресурса Azure свой адрес, общего нет. Адрес не
    # секрет — потому здесь, а не в secrets.yaml. Без него коннектор откажет,
    # назвав именно адрес, а не пойдёт в чужой ресурс.
    endpoint: "https://ИМЯ-РЕСУРСА.cognitiveservices.azure.com"
    daily_quota: 160          # суточная доля от 5000/мес на бесплатном F0
  faceplusplus:
    consent: false            # лица — только осознанно, даже без поиска по сети
    daily_quota: 50
  social-analyzer:
    top: 50                   # сколько сайтов обходить (900 — это минуты)
```

Блока `connectors` может не быть вовсе — тогда всё выключено, и это правильное
значение по умолчанию.

**Адрес Azure перепутать легко, и ключ этого не заметит.** У одного ресурса их
три, ключ на всех общий, а службы разные:

| Адрес | Что это | Годится сюда |
|-------|---------|--------------|
| `…services.ai.azure.com/api/projects/…` | Foundry-проект | нет |
| `…openai.azure.com/openai/v1` | Azure OpenAI (GPT) | нет |
| `…cognitiveservices.azure.com` | **Image Analysis** | да |

Первые два в портале попадаются на глаза первыми, и подставленные сюда дают 404
на ровном месте — при полностью исправном ключе.

## Готовые коннекторы

| Имя | Что делает | Ключ | Согласие |
|-----|-----------|------|----------|
| `azure-vision` | Что изображено на картинке; текст с картинки (OCR) | `azure_vision_key` + `endpoint` в settings | **обязательно** |
| `faceplusplus` | Сравнить два лица; разобрать лицо в кадре | `faceplusplus_api_key` + `faceplusplus_api_secret` | **обязательно** |
| `social-analyzer` | Профили по нику на сотнях сайтов | не нужен (pip-пакет) | **обязательно** |
| `translator` | Перевод текста, офлайн-движком | не нужен (pip-пакет) | не требуется |

Фразы — в конце `config/commands.yaml`, перед хвостовым `открой *`:
«прочитай текст с картинки …», «что на картинке …», «опиши картинку …»,
«сравни лица … и …», «что за лицо …», «сколько лиц …», «найди профили …»,
«найди аккаунты …», «переведи … [на английский]», «как будет … по-английски».

«Прочитай текст» стоит **перед** «что на картинке»: обе фразы про картинку, но
`features` у них разные — и цена вызова, и ключ кеша. Порядок правил здесь и
решает, какая сработает; на это есть тест.

### Картинку Джони берёт и сам

Всем фразам выше нужен путь к файлу или ссылка. Отдельный набор команд снимает
картинку на месте — `johnny/capture.py`, четыре источника:

| Источник | Фразы | Что снимает |
|----------|-------|-------------|
| `screen` | «что на экране», «прочитай что на экране», «опиши экран» | все мониторы сразу |
| `region` | «что вот здесь», «опиши выделенное», «прочитай выделенное» | область, выделенную мышью |
| `window` | «что в окне», «прочитай текст из окна» | активное окно |
| `camera` | «что видит камера», «посмотри в камеру» | один кадр с веб-камеры |

Мышью то же самое — карточки «Что я вижу» и «Текст с экрана» в разделе
«Тулкиты»: вместо поля с путём список источников (вписывать туда нечего, файла
ещё нет).

Приватность здесь устроена в два слоя, и оба важны:

- **Согласие захват НЕ обходит.** Он лишь делает файл; отправку наружу
  по-прежнему решает `requires_consent` у `azure-vision`.
- **Файл не переживает ответ.** Снимок лежит в `models/captures/` (каталог
  `models/` целиком в `.gitignore`) и удаляется в `finally` — и при отказе
  коннектора, и при исключении. На снимке экрана бывает чужая переписка, и
  «оставим на случай отладки» — цена, которой этот случай не стоит.

Выделение области показывается **отдельным процессом**
(`python -m johnny.region_select`), а не окном внутри Джони: панель держит свой
Tk-цикл в своём потоке, тулкиты выполняются в фоновом, и Tk из чужого потока
вешает панель молча, без исключения. Экран при этом снимается ДО показа рамки —
иначе полупрозрачная плёнка оверлея попала бы в кадр, и OCR читал бы текст
сквозь неё.

Результат распознавания уходит в короткую память (чтобы следом работало
«переведи это»), но в вечные факты — только по отдельной команде «запомни что
на экране»: факты живут до «забудь» и уезжают в промпт каждой модели.

### Чего эти два коннектора не делают

Обратного поиска картинки («откуда эта картинка») и поиска человека по лицу в
интернете больше нет, и это не недоделка. У Azure нет поиска по индексу
интернета вовсе — тот, что был у Microsoft (Bing Visual Search), закрыт; Face++
по сети не ходит и сравнивает только те два снимка, которые ему дали. Фразы
убраны из `commands.yaml`, а тест падает, если `reverse_image` или `face_search`
вернутся: обещать команду, которой нет, хуже, чем не иметь её вовсе.

Оба вопроса при этом остались без исполнителя, и решение владельца по ним не
закрыто: **TinEye и FaceCheck.ID, возможно, придётся вернуть.** Аналогов у
Azure и Face++ нет — если понадобится «откуда эта картинка» или «кто этот
человек», вернуть надо именно их, и не вместо, а рядом. Что для этого нужно
тронуть, перечислено в `docs/superpowers/plans/details/integrate_tineye_connector.md`
и `integrate_facecheck_connector.md`; тест-сторож снимается тем же решением, в
одном коммите с возвратом команды.

Взамен закрыт другой пункт плана — OCR и распознавание объектов: `features=read`
даёт текст со скриншота, `features=caption,tags,objects` — описание и объекты.

Описание Azure отдаёт **по-английски**: русского у него нет, `language`
поддерживает только en/es/ja/pt/zh. Поэтому ответ так и начинается — «на
картинке (по-английски): …», иначе английская фраза посреди русского ответа
выглядит как сбой. Текст со скриншота (`read`) при этом возвращается на своём
языке, и OCR по-русски работает.

#### Регион ресурса решает, что вообще доступно

Проверено на живом ресурсе, а не по документации: в **swedencentral** `caption`
отвечает `400 The feature 'Caption' is not supported in this region` при
исправном ключе и правильном адресе. `read`, `tags` и `objects` там работают.

`caption` стоит первым в `DESCRIBE_FEATURES`, а Azure отвергает **весь** запрос
целиком — то есть «что на картинке» не работала бы никогда, и человек слышал бы
«azure-vision не ответил» без намёка на причину. Поэтому коннектор снимает
недоступную фичу и переспрашивает остатком: имя фичи читается из самого
сообщения, чтобы не потерять заодно `tags` и `objects`.

Повтор ровно один и только из-за региона: 401 и 429 от повтора не чинятся, а
квоту тратят вдвое. Результат запоминается **в модуле**, а не в объекте —
коннектор пересобирается фабрикой на каждый вызов, и память внутри объекта не
пережила бы даже второй запрос. На диск не пишется: ресурс могут пересоздать в
другом регионе, и записанное «caption тут нет» врало бы молча и навсегда.

Ответ без `caption` звучит перечислением — «Вижу на картинке (по-английски):
person, grass, soccer player». Писать в этом случае «Описания нет» неправильно:
человек слышит отказ, хотя ответ есть, просто списком.

Альтернатива обходу — **создать ресурс Vision в регионе, где `caption` есть**
(например, eastus или westeurope). Тогда вернётся полное описание фразой вместо
списка слов. Обход при этом не мешает и остаётся страховкой.

Вердикт Face++ считается по порогу **из самого ответа**, и по самому строгому из
трёх (`1e-5`): «сходство 82» само по себе не значит ничего. Порог всегда
произносится вслух рядом со сходством — иначе человеку предлагается сделать
вывод по числу, которое не с чем сравнить. Мутный кадр отмечается отдельно: по
нему сравнение выдаёт уверенное «не тот человек», и сказать об этом надо раньше,
чем человек сделает вывод.

Снимок уходит **файлом**, а не ссылкой, и это не только про приватность. На
живом ключе `image_url` отвечает `INVALID_IMAGE_URL` даже на публично доступные
картинки — Face++ скачивает их сам и часто не может. Путь с загрузкой файла
проверен и работает; `image_url` коннектор не использует вовсе.

### Переводчик: локально вперёд сети

`translator` — единственный, у кого два движка сразу, и порядок между ними
жёсткий: сначала локальный `argostranslate`, в сеть — только если нужной пары
языков нет локально **и** адрес вписан руками.

```bash
pip install argostranslate
```

Адрес по умолчанию пустой сознательно: публичный инстанс по умолчанию означал
бы, что любой продиктованный текст молча уезжает на чужой сервер. Запасной путь
— LibreTranslate (`docker run -p 5000:5000 libretranslate/libretranslate`), и он
выбран не случайно: LibreTranslate собран на том же argostranslate, поэтому
удалённый ответ совпадает с локальным, а не звучит переводом «другим голосом».

Язык разбирает действие, а не `commands.yaml`: «на английский», «на английском»,
«по-английски» — одно правило на все языки вместо полутора десятков почти
одинаковых, которые к тому же перекрыли бы общее «переведи \*» по порядку файла.
Без указания языка русский текст идёт в английский, любой другой — в русский.

## Кнопки в панели

Те же коннекторы доступны мышкой: раздел **Тулкиты** в панели настроек
(трей → «Настройки»). Карточка на каждое **действие**, а не на коннектор: у
`azure-vision` их два («что на картинке» и «прочитай текст»), у `faceplusplus`
тоже два, и различаются они только параметрами вызова — по имени коннектора
вторая карточка затирала бы первую.

Поле ввода, кнопка и строка состояния; у всего, что работает с картинкой, ещё
кнопка «Обзор», потому что печатать путь к файлу руками — это опечатка в пути
вместо ответа. У «сравни лица» «Обзор» **дописывает** второй снимок к первому, а
не затирает его: за два нажатия набирается пара.

Кнопка идёт через `registry.execute`, **не** напрямую в коннектор. Это главное
решение в `johnny/panel_tools.py`: иначе разбор языка, выковыривание ссылки из
фразы и текст отказов пришлось бы писать заново, и голос с кнопкой разошлись бы —
кнопка отвечает одно, голос другое, а править надо в двух местах.

Под полем написано, как это же сказать голосом. Панель заодно оказывается
ответом на «а что Джони вообще умеет».

Строка состояния показывает не «готов/не готов», а **что сделать**: какой ключ
вписать, какое согласие включить, какой пакет поставить — это `available()`
коннектора дословно. Проверка идёт в фоновом потоке: `available()` у
social-analyzer и переводчика импортирует пакет, и на первом разе это заметная
пауза, которая иначе подвесила бы окно.

Кнопка на время работы гаснет. Не косметика: второй клик по Azure Vision или
Face++ — это второй списанный запрос из оплаченного пакета.

Ответ из фонового потока возвращается через очередь (`panel_tools.drain`), а не
через `self.after`. `after` сам по себе вызов в Tcl и из чужого потока падает
«main thread is not in main loop» — на этом уже наступили один раз. Упавшее
задание очередь не останавливает: иначе первая же ошибка навсегда заморозила бы
все тулкиты, и выглядело бы это как «панель сломалась».

## Диск

Всё лежит в `models/connector-cache/` (каталог уже вне git):

- `<sha1>.json` — ответ с меткой времени; TTL по `ttl_seconds`.
- `state.json` — счётчик вызовов за сутки и время последнего, **между
  запусками**. В памяти его держать нельзя: Джони за вечер правок
  перезапускается десятки раз, и суточная квота сгорела бы за час, молча.
- Запись через `.part` + `os.replace`; осиротевшие `.part` подчищает `trim()`.
- Битый файл кеша удаляется при чтении: иначе он вечно выглядит как «кеш есть»
  и блокирует живой запрос.

`time.time()`, а не `monotonic()` — TTL и суточный счёт обязаны пережить
перезапуск. `monotonic()` остаётся для cooldown внутри процесса.

## Тестирование

```bash
pytest tests/test_connector_base.py tests/test_connector_factory.py tests/test_connector_actions.py -v
```

Отдельные коннекторы — `tests/test_azure_vision_connector.py`,
`tests/test_faceplusplus_connector.py`, `tests/test_social_analyzer_connector.py`,
`tests/test_translator_connector.py`. Кнопки — `tests/test_panel_tools.py`
(без Tk: виджеты в тестах не поднять, а «что уйдёт в действие», «готов ли
коннектор» и разбор очереди ответов — можно).

Тест коннектора **обязан** изолировать два источника протечек, оба уже
срабатывали:

```python
@pytest.fixture(autouse=True)
def _isolated(tmp_path, monkeypatch):
    monkeypatch.setattr(http_client, "_last_failure", {})   # cooldown — модульный словарь
    monkeypatch.setattr(base, "DEFAULT_CACHE_DIR", tmp_path)  # иначе пишем в реальный проект
```

Второе особенно важно: `cache_dir=""` — это ложь, и коннектор молча уходит
писать в настоящий `models/connector-cache`. Тест при этом проходит, а мусор
остаётся в рабочем каталоге.

Ещё две вещи, на которых спотыкаешься при написании такого теста:

- `min_interval_seconds`, `daily_quota`, `ttl_seconds`, `requires_consent` —
  **атрибуты класса**, а не аргументы конструктора. В тесте их присваивают уже
  собранному объекту (`connector.min_interval_seconds = 0`), иначе прогон
  удлиняется паузами, которые и так проверены в `test_connector_base.py`.
- Исключение из `_run` наружу выходит **обобщённым**: человек слышит
  «`<имя>` не ответил», а настоящая причина лежит в `result.data["error"]`.
  Проверять детали ошибки надо там, а не в `result.message`.

И одна ловушка в проверках самих: искать подстроку в записи журнала («нет ли тут
возраста 31») нельзя — «31» встретится внутри хеша файла, и такая проверка врёт в
обе стороны. Сравнивать надо набор полей целиком:
`set(record) == {"at", "mode", "files", "hashes", "faces"}`.

## Ограничения и рекомендации

- Имя коннектора (`name`) — ключ кеша, квоты, cooldown и строк в логе. У
  каждого своё, иначе отказ одного сервиса глушит попытки к остальным.
- `daily_quota = 0` — без лимита. Ставить реальную цифру тарифа: смысл счётчика
  в том, чтобы бесплатный тариф не кончился в первый же вечер отладки.
- Интервал между вызовами выжидается на своей стороне: 429 от сервиса тратит
  квоту и попадает под cooldown, глуша следующий вызов.
- Ответ из кеша произносится как обычный: для человека это офлайн-режим, а не
  сбой, и сообщать о нём незачем.
- Все HTTP-запросы — через `johnny/http_client.py`: он подставляет браузерный
  `User-Agent`, без которого Cloudflare отвечает «error code: 1010».
