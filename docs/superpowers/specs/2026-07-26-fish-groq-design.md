# Голос Джарвиса и быстрые ответы: fish.audio + Groq

**Дата:** 2026-07-26
**Статус:** дизайн утверждён

## Проблема

Джони отвечает медленно и чужим голосом.

| Звено | Сейчас | Замерено |
|---|---|---|
| Ответ на вопрос | `claude -p` (CLI) | 2.9–5.3 с |
| Озвучка | edge-tts, голос «Дмитрий» | 1–2 с |
| **Итого от конца фразы до звука** | | **4–7 с** |

Разговором это не ощущается. Плюс голос Дмитрия — не голос Джарвиса, ради
которого всё затевалось.

Локальный XTTS решает вторую задачу, но занимает 2.3 ГБ видеопамяти. Замер во
время Apex: занято 6.0 из 8.2 ГБ, включая Whisper Джони (2.1 ГБ) — свободного
запаса ровно столько, сколько съел бы XTTS. Значит, локальный синтез отбирает
возможность разговаривать с Джони во время игры.

## Замеры, на которых стоит дизайн

Все цифры получены на этой машине, не из документации.

| Что | Результат |
|---|---|
| fish `s2.1-pro-free`, «Да, сэр» (5 запросов) | 0.47 с в среднем |
| fish, фраза 57 символов | 0.78–1.78 с |
| fish, видеопамять | 0 |
| Groq `llama-3.3-70b-versatile`, короткий ответ | 0.19 с |
| Groq, ответ на вопрос по-русски | 0.54 с |
| `claude -p`, запуск CLI | 0.1 с (остальное — сеть и модель) |
| XTTS локально: загрузка / синтез / видеопамять | 5.2 с / 0.5–2.4 с / 2.31 ГБ |

Итог: облако быстрее локальной видеокарты и не трогает видеопамять вовсе.

Модель голоса на fish создана из русского дубляжа: 14 минут нарезок → Demucs
(`htdemucs_ft`) снял музыку → отбор по отношению фона к голосу (порог 0.10) →
ранжирование по близости тембра → 8 кусков, 46 с. `model_id`
`81d5531b63c8459790f5a625ed5de915`.

## Решение

Три независимых куска: голос, кеш повторяющихся фраз, мозг.

### 1. Голос: ещё одно звено в цепочке

```
fish-Джарвис  →  edge-Дмитрий  →  pyttsx3
  0.5–1.4 с       нет fish/ключа     нет сети совсем
```

`speaker.py` уже устроен как «основной синтез + запасной» (`_make_edge_tts(voice,
fallback)`). Добавляем звено тем же способом, `Speaker` не меняется.

Новый модуль `johnny/tts_fish.py`:

* `synthesize(text, api_key, model_id, timeout) -> bytes` — POST
  `https://api.fish.audio/v1/tts`, заголовки `Authorization`, `model:
  s2.1-pro-free`, `User-Agent` (браузерный), тело
  `{"text": ..., "reference_id": model_id, "format": "mp3"}`. Возвращает mp3.
* `make_fish_tts(api_key, model_id, fallback, cache_dir) -> say(text)` — кеш,
  синтез, проигрывание через `sounds.play_file`; любая ошибка → `fallback(text)`.

**Браузерный `User-Agent` обязателен.** И fish, и Groq стоят за Cloudflare,
который отдаёт `error code: 1010` любому клиенту без него. Заголовок помечен
комментарием, чтобы его не «прибрали» как лишний.

### 2. Кеш повторяющихся фраз

Служебные фразы Джони («Не понял команду», «Не расслышал», «Не смог выполнить
команду», «Слушаю») звучат сотни раз. Гонять их в облако каждый раз — лишняя
секунда и лишний расход бесплатного тарифа.

* Файл: `models/tts-cache/<sha1(text)>.mp3` (`models/` в `.gitignore`).
* Кешируем только короткие фразы, **не длиннее 40 символов**: служебные реплики
  в этот предел укладываются все, ответы модели — почти никогда, а они
  дословно не повторяются, и кешировать их значит копить мусор.
* Запись атомарная: во временный файл рядом, затем `os.replace`. Оборванный
  ответ сети не должен остаться в кеше «навсегда».
* Потолок — **100 файлов**; при превышении удаляются самые старые по `mtime`.
* Попадание в кеш играется мгновенно и без сети — заодно страховка: частые
  фразы звучат Джарвисом даже при отвалившемся интернете.

### 3. Мозг: Groq впереди, Claude сзади

Сейчас `claude_brain.py` держит вперемешку промпт, разбор ответа, защиту от
разрушительных команд и запуск CLI. Скопировать это под Groq — значит завести
второй экземпляр логики, который со временем разъедется с первым. Поэтому
раскладываем по ответственности:

```
johnny/brain.py          промпт, разбор ответа, защита, порядок провайдеров
   ├── brain_groq.py     prompt -> text (HTTP)
   └── brain_claude.py   prompt -> text (CLI, нынешний код без изменений)
```

Провайдер — функция `(prompt: str) -> str`. Пустая строка означает «не смог,
пробуй следующего». Провайдеры ничего не знают ни про команды, ни про JSON.

* `brain.make_providers(config) -> list[provider]` — Groq первым, если в
  секретах есть ключ; Claude всегда последним.
* `brain.interpret(text, commands=None, providers=None) -> BrainResult | None` —
  перебирает провайдеров до первого непустого ответа, разбирает его. Все
  проверки безопасности переезжают как есть: исправленная фраза проходит
  обычный `route()`, `is_unsafe_action` отклоняет разрушительный результат,
  разрушительные правила не показываются модели вовсе.
* `ClaudeResult` → `BrainResult` (то же поле в поле): имя «Claude» перестало
  быть правдой.

Groq: POST `https://api.groq.com/openai/v1/chat/completions`, модель
`llama-3.3-70b-versatile`, одно сообщение с промптом, `temperature` 0.3.

### Что получится по времени

```
было:  Claude 3–5 с   + edge 1–2 с     = 4–7 секунд
стало: Groq 0.2–0.5 с + fish 0.5–1.4 с = 1–2 секунды
```

Видеопамять не меняется: как было 2.1 ГБ на Whisper, так и остаётся. Играть в
Apex и разговаривать с Джони можно.

## Конфигурация

`config/secrets.yaml` (в `.gitignore`, файл необязательный):

```yaml
groq_api_key: "..."
fish_api_key: "..."
```

`config/settings.yaml` — новые поля:

```yaml
tts_provider: fish            # fish | edge
fish_model_id: "81d5531b63c8459790f5a625ed5de915"
groq_model: "llama-3.3-70b-versatile"
```

`Config` получает поле `secrets: dict` (пустой словарь, если файла нет).
Ключей нет → Джони молча работает на Дмитрии и Клоде, ровно как сегодня.

Голос Джарвиса включается только при выполнении всех условий сразу:
`response_mode: voice`, `tts_provider: fish`, непустой `fish_api_key` в
секретах и непустой `fish_model_id`. Любое не выполнено — сразу edge-Дмитрий.
Groq включается при непустом `groq_api_key`.

`make_speaker` меняет сигнатуру: вместо `(mode, tts_voice)` — `(settings,
secrets)`. Ему теперь нужны четыре настройки, а режим и так лежит в
`settings.response_mode`; оба вызова (`app.py`, `tray.py`) становятся
одинаковыми.

## Обработка ошибок

Общее правило: **не падать, а сходить на ступень ниже**.

| Что сломалось | Что происходит |
|---|---|
| fish: сеть, таймаут (10 с), код ≠ 200 | синтез уходит на edge-Дмитрия |
| edge тоже недоступен | pyttsx3 (офлайн) |
| Groq: нет ключа, сеть, таймаут (10 с), код ≠ 200 | вопрос уходит в `claude -p` |
| Claude тоже молчит | «Не понял команду», как сегодня |
| Кеш: битый или нечитаемый файл | синтезируем заново |

Ошибка каждого вида логируется **один раз за запуск** (`warn_once`), дальше — в
`debug`. Без этого пропавший интернет заливает `johnny.log` трейсбеком на каждую
фразу; на это уже наступали в цикле прослушивания.

Общий для fish и Groq модуль `johnny/http_client.py`: браузерный `User-Agent`,
POST с таймаутом, `warn_once`.

## Тестирование

Живой сети в тестах нет — HTTP подменяется.

| Файл | Что проверяет |
|---|---|
| `tests/test_tts_fish.py` | попадание в кеш не ходит в сеть; промах пишет файл и играет его; ошибка HTTP → вызван fallback; оборванный ответ не остаётся в кеше; потолок в 100 файлов удаляет самые старые; длинный текст не кешируется |
| `tests/test_brain.py` | (бывший `test_claude_brain.py`) разбор ответа, коррекция через `route`, отказ от разрушительных действий; первый провайдер ответил → второй не вызван; первый вернул пусто → отвечает второй; все пусты → `None` |
| `tests/test_brain_groq.py` | запрос содержит ключ, модель и `User-Agent`; ответ распакован из JSON; код ≠ 200 → пустая строка |
| `tests/test_config.py` | секреты читаются; файла нет → `{}`; значения по умолчанию для новых настроек |
| `tests/test_speaker.py` | новая сигнатура; fish выбирается при наличии ключа и `model_id`, иначе edge |

Живая проверка голосом — отдельно, руками, после сборки: сказать «Джони,
привет» и «Джони, кто такой Тони Старк», послушать голос и замерить паузу.

## Чего сознательно не делаем

* **Локальный XTTS как запасной вариант.** Решено при обсуждении: нет fish —
  хватит Дмитрия. Держать 2.3 ГБ видеопамяти и второй venv ради запасного
  голоса не стоит.
* **Потоковый синтез (по кускам, с проигрыванием на лету).** Ответы Джони —
  1–3 предложения, целиком синтезируются за 0.5–1.4 с. Сложность потока
  оправдана на длинных текстах, у нас их нет.
* **Выбор голоса из трея.** Правится строкой в `settings.yaml`.
* **Кеш ответов модели.** Ответы не повторяются дословно.
* **Свой ключ на каждого провайдера в `settings.yaml`.** Ключи живут только в
  `secrets.yaml`, чтобы их нельзя было закоммитить случайно.
