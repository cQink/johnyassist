# Цепочки команд

Дата: 2026-07-27

## Задача

Одна фраза — несколько действий. Три случая, ради которых это делается:

1. **Связанные браузерные**: «найди Exile Show на ютубе и включи первое видео на весь экран». Второй шаг зависит от первого — нужно дождаться загрузки страницы.
2. **Независимые действия**: «запусти OBS и сделай громкость 30».
3. **Сценарии одним словом**: «режим стрима» = запустить OBS + открыть твич + громкость 20. Набор задаётся в конфиге, модель не участвует.

У всех трёх общее ядро — «выполнить список действий по очереди». Различается только источник списка.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Кто разбивает фразу | Локальный сплит по союзам с проверкой; модель запасным | Частые цепочки известных команд работают мгновенно, бесплатно и без сети |
| Провал шага в середине | Всегда стоп, дальше не идём | Шаги чаще связаны; фуллскрин без видео развернёт чужую вкладку |
| Отчёт об успехе | Один звук в конце на всю цепочку | Три «Roger that» подряд за две секунды — шум |
| Опасные действия в цепочке | Запрещены полностью | Единственный способ их произнести остаётся прежним: точное совпадение целой фразой |

## Устройство

Новый модуль `johnny/chain.py` с одной ответственностью: превратить фразу в список шагов и выполнить его.

### Порядок разбора в `handle_command`

```
1. точное совпадение с шаблоном БЕЗ «*»   → одиночная команда
2. chain.split_local (все куски точно)    → цепочка
3. обычный route() (шаблоны + нечёткое)   → одиночная команда
4. brain.interpret                        → шаги или одиночное
```

Порядок именно такой, и это не косметика:

- **Ступень 1** защищает фиксированную фразу, внутри которой есть «и», от ножа сплиттера. Такая фраза — заведомо одна команда.
- **Ступень 2 идёт впереди жадных шаблонов.** В `commands.yaml` есть `"запусти *"`, и «запусти обс и громкость 20» совпадает с ним **точно**, с аргументом `"обс и громкость 20"`. Поставь сплиттер после — и цепочки из таких фраз не будет никогда.
- **Ступень 3** — сегодняшнее поведение, без изменений.

### Общая точка сборки

Все три источника списка сходятся в одну функцию:

```python
chain.resolve(phrases: list[str], commands) -> list[RoutedAction] | None
```

Каждая фраза прогоняется через `route_exact()`. Если хоть одна не разобралась — `None`, цепочки нет.

Сигнатура точного матчинга — с явным различением двух режимов, они оба нужны:

```python
route_exact(text, commands, *, literal_only: bool = False) -> RoutedAction | None
```

`literal_only=True` игнорирует шаблоны со «звёздочкой» и совпадает только с фиксированными фразами — это ступень 1. По умолчанию (`False`) участвуют и шаблоны — это то, чем пользуются сплиттер и `route()`.

Отсюда главное свойство безопасности: **модель не изобретает действия, она предлагает только фразы**. Ровно тот же приём уже применён к `{"command": ...}` в `brain.py`, и он же не даёт модели собрать кривой аргумент или выдумать несуществующее действие.

### Сплиттер

`chain.split_local(text, commands) -> list[RoutedAction] | None`

Разделители: `и`, `потом`, `затем`, `а потом`, `а также`, `плюс`. Режем **только по отдельным словам**, не по подстроке — иначе «игра», «или», «история» распадутся.

Разбиение принимается, только если выполнено всё:

- кусков ≥ 2;
- каждый кусок совпал **точно** (`route_exact`, без нечёткого);
- кусков ≤ 5;
- ни один шаг не опасен.

Иначе разбиение отбрасывается молча, будто сплиттера не было, и фраза идёт на следующую ступень целой.

Нечёткое сравнение внутрь кусков не пускается сознательно: оно и на целых фразах иногда мажет, а здесь ошибка тихо утащит половину цепочки не туда, и человек этого не услышит.

**Известная цена.** Если оба куска случайно окажутся настоящими командами, фраза разделится не так, как задумано. Живой пример: «найди на ютубе рок и включи музыку» — «включи музыку» это алиас снятия паузы, и Джони поймёт фразу как две команды. Обходится тем, что аргумент договаривается без «и». Требование точного совпадения каждого куска делает такие случаи редкими: «найди на ютубе рок и ролл» разбиение не проходит («ролл» ни с чем не совпадает) и уходит в поиск целой фразой.

### Сценарии

`config/scenarios.yaml`, ключ = фраза, значение = список шагов:

```yaml
режим стрима:
  - запусти обс
  - открой твич
  - громкость 20
```

`load_config` превращает каждый ключ в обычный `CommandRule(action="scenario", template=<ключ>)`. Даром достаётся вся лестница совпадений: «режим стрима» поймается точно, «режым стрима» — нечётко.

Файл опционален: его отсутствие не ломает старт, как сейчас у `channels.yaml`.

Вложенность запрещена — шаг с `action="scenario"` внутри сценария отвергается. Рекурсии нет.

Сценарий **не выполняется** через `actions.execute`: это не действие над системой, а список фраз. `handle_command`, получив `RoutedAction(action="scenario")`, разворачивает его в цепочку через `chain.resolve(config.scenarios[имя])` и дальше идёт общим путём. `actions.py` про сценарии не знает вовсе.

### Выполнение

```python
chain.run(actions, config, speaker) -> ChainResult(done: int, total: int, failure: str | None)
```

По очереди `execute()`. Первый `ok=False` останавливает остаток. Звук успеха играется один раз в конце. При провале — фраза «Сделал N из M, не смог: `<сообщение шага>`».

`chain.run` возвращает свой маленький результат, а не `Outcome` из `app.py`, **чтобы не было кольцевого импорта**: `app` импортирует `chain`, значит `chain` не может импортировать `app`. `Outcome` для истории собирает `app.handle_command` по `ChainResult`.

В `history.log` строка вида `цепочка(3)/локально` или `цепочка(2)/groq` — чтобы было видно, кто разбирал и как часто нужна модель.

## Ожидание в браузере

Без этого связанные цепочки не работают, поэтому это часть итерации, а не «потом».

**Сегодняшний дефект.** `browser.click_result` — это `if(el) el.click()`. Если результаты поиска ещё не загрузились, список пуст, функция молча ничего не делает и возвращает `None`, а `actions.execute` отвечает `ok=True`. То же у `next_video` и `fullscreen`. Связанная цепочка сегодня не только не дождалась бы страницы — она не смогла бы и сообщить о провале, а весь «стоп при провале» держится именно на этом сигнале.

Добавляется один общий примитив:

```python
def _wait_for(script, timeout=8.0) -> bool:
    """Опрашивает страницу (раз в 0.25с), пока скрипт не вернёт истину."""
```

Через уже существующий `get_driver().execute_script`. Не `WebDriverWait` со своими локаторами: вся работа со страницей в проекте уже написана на JS, второй способ обращения ради одной функции не нужен.

Поверх него три функции меняют контракт с «молча ничего» на `bool`:

| Функция | Чего ждёт | Возвращает |
|---|---|---|
| `click_result(n)` | в списке результатов есть n-й элемент | кликнул или нет |
| `fullscreen()` | появилась `.ytp-fullscreen-button` | нажал или нет |
| `next_video()` | появилась `.ytp-next-button` | нажал или нет |

Все три принимают `timeout` параметром (по умолчанию 8с) — иначе тест на истечение таймаута пришлось бы ждать восемь секунд.

`actions.execute` переводит `False` в `ActionResult(False, "Не нашёл видео на странице")`. Это чинит и одиночные команды: сегодня «включи первое видео» на незагруженной странице отвечает бодрым «Roger that», не сделав ничего.

Таймаут 8с — верхняя граница, а не задержка: обычно результаты отрисовываются за 0.3–1с и шаг идёт дальше сразу. Худший случай — 8с молчания перед «не нашёл видео», и только когда что-то действительно сломалось.

У YouTube кнопка фуллскрина появляется только когда плеер уже на странице, поэтому «включи первое видео на весь экран» — две ступени ожидания подряд, и они складываются. Для этого и нужен стоп при провале: если видео не открылось, фуллскрин не станет разворачивать чужую вкладку.

## Изменения в существующем коде

- `router.py`: выделить `route_exact(text, commands)` — то, что сейчас первый цикл внутри `route()`. Извлечение, а не новый флаг; `route()` начинает вызывать её саму, поведение не меняется.
- `app.handle_command`: новый порядок разбора (см. выше).
- `brain.py`: в промпт добавляется случай «несколько команд в одной фразе» → `{"steps": ["фраза1", "фраза2"]}`; разбор через `chain.resolve`.
- `config.py`: чтение опционального `scenarios.yaml`.
- `actions.py`: честный `ok=False` от браузерных функций. Сценарии сюда не попадают.
- `browser.py`: `_wait_for` и три функции, возвращающие `bool`.

## Безопасность

- **Опасные действия (`shutdown`/`restart`/`sleep`) запрещены в цепочках полностью** — на всех трёх источниках, через существующий `is_unsafe_action`. Правило «только точное совпадение целой фразой» остаётся единственным способом их произнести. Стоимость запрета нулевая.
- **Потолок 5 шагов** на любую цепочку, включая ту, что вернула модель.
- **Никакой рекурсии сценариев.**

## Тестирование

Почти вся новая логика — чистые функции, поэтому основное закрывается юнит-тестами без микрофона и без сети.

**Сплиттер** (плотнее всего, потому что ошибка тихая):
- «запусти обс и громкость 20» → два шага;
- «найди на ютубе рок и ролл» → `None`, фраза остаётся целой;
- один кусок → `None`;
- 6 шагов → `None`;
- «сверни всё и выключи компьютер» → `None`;
- разделители «потом / затем / а также / плюс» работают;
- «и» внутри слова не режет: «игра», «или», «история».

**Порядок разбора** — главный регрессионный тест итерации: «запусти обс и громкость 20» обязана стать цепочкой, а не `launch_app("обс и громкость 20")`.

**`route_exact`**: все существующие тесты `route()` остаются как есть и служат страховкой, что извлечение ничего не изменило.

**Сценарии**: загрузка даёт правила; отсутствующий файл не ломает старт; вложенный сценарий отвергается.

**Выполнение** на поддельных `speaker`/`execute`: стоп ровно на первом провале, звук ровно один, сообщение «Сделал 1 из 3».

**Модель**: `{"steps": [...]}` роутится; нераспознанный шаг отвергает всю цепочку; опасный шаг отвергается; потолок 5 действует и здесь.

**Браузер**: поддельный драйвер, чей `execute_script` возвращает 0 первые несколько опросов и потом 1 — `_wait_for` дожидается, а по таймауту честно отдаёт `False` (таймаут в тестах 0.1с). Плюс `actions`: `False` от браузера превращается в `ActionResult(ok=False)`.

**Живая проверка** (только пользователь, автотесты реальный YouTube не покрывают): независимая цепочка, связанная браузерная, сценарий.
