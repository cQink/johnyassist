# Итерация «Мультимониторность» — дизайн

**Дата:** 2026-07-25
**Статус:** согласован

## Раскладка мониторов (у пользователя)
- Монитор 1 — 2560×1440, основной, слева (X=0)
- Монитор 2 — 1920×1080, справа (X=2560)

Порядок «1/2» = слева направо (по координате X).

## Голосовые имена мониторов (все поддерживаются)
- «первый / левый / основной / главный монитор» → 1
- «второй / правый монитор» → 2

## Команды
1. **Перенести текущее окно** (`move_window`): «на второй монитор»,
   «перенеси на второй монитор», «скинь на правый монитор» → активное окно
   переезжает на нужный экран и разворачивается. Надёжно.
2. **Открыть на мониторе** (`launch_on_monitor`): «открой браузер на втором
   мониторе» → запускает программу из apps.yaml, ждёт ~2.5 c, переносит
   появившееся (переднее) окно. Работает для программ, открывающих своё окно;
   для сайтов/уже открытых программ ненадёжно (ограничение таймингов Windows).

## Модуль `johnny/windows.py` (pywin32, ленивый импорт)
- `list_monitors() -> list[rect]` — прямоугольники мониторов слева направо.
- `pick_monitor(monitors, index) -> rect | None` — по 1-based номеру (чистая
  функция, тестируется).
- `move_window_to_monitor(hwnd, monitors, index) -> bool` — восстановить,
  подвинуть на целевой монитор, развернуть.
- `move_foreground_to_monitor(index) -> bool` — активное окно (интеграция).

## Действия (`actions.py`)
- `move_window(index)` — перенести переднее окно; ветка в `execute()`.
- `launch_on_monitor(argument, apps)` — argument = «имя|номер»; запустить
  приложение, пауза, перенести переднее окно.

## Тесты
- `pick_monitor` (чистая логика выбора).
- `move_window_to_monitor` с моками win32gui (проверяем координаты).
- Диспетч действий `move_window` / `launch_on_monitor` (парсинг «имя|номер»).
- Реальный перенос окна — вживую на машине пользователя.

## Вне итерации (следующие)
Медиа-клавиши (пауза/след./пред. трек) и глубокое управление YouTube/Spotify
(клик по результату, перемотка на время, плейлист) — требуют автоматизации
браузера, проектируем отдельно.
