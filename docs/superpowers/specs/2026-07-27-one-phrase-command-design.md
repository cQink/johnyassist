# Команда одной фразой (слитный вызов)

Дата: 2026-07-27

## Задача

Сегодня Джони понимает только двухтактный вызов: «Джони» → дождаться звука →
«громкость пять». Нужно говорить слитно, одной фразой, не дожидаясь
подтверждения. Двухтактный режим при этом сохраняется: звук-подтверждение
должен звучать тогда — и только тогда — когда после имени была пауза. Это
не только удобство: пауза с ответным звуком — способ убедиться, что Джони
слышит, и она делает его живее.

## Почему сейчас не работает

Между именем и командой микрофон физически не пишет:

1. `listener.py` — Vosk открывает **свой** поток (`RawInputStream`, блок 0.5с),
   ловит «джони», закрывает поток и **чистит хвост очереди** (строки 41–42).
2. `controller.py:61` — играет ack-звук (mp3 через MCI, блокирующе, ~0.5–1с).
3. `recognizer.py:142` — Whisper открывает **второй** поток и только тогда
   начинает запись.

Всё сказанное между шагами 1 и 3 теряется безвозвратно. Этим же объясняется
давняя жалоба «первые два раза не услышал».

## Решение: один общий микрофонный поток

Микрофон открывается один раз на всё время работы. Vosk и Whisper читают
блоки из общего источника, поток между этапами не прерывается. Кольцевой
буфер хранит последние 1.5с, поэтому после срабатывания вейкворда доступен
звук **до и включая само имя**.

Отвергнутые варианты:

- **Быстрый хак без общего потока** (сразу открыть Whisper-поток после
  вейкворда, без звука, с коротким `start_timeout`). Открытие WASAPI-потока
  — 50–200мс, и они приходятся ровно на первый слог команды; слово «Джони»
  остаётся в закрытом потоке, восстановить якорь нечем.
- **Микрофоном владеет `Listener`** (Vosk держит поток и сам отдаёт хвост).
  По качеству звука равноценно, но `Listener` получает две роли — «ловец
  слова» и «владелец устройства», — что помешает следующей задаче
  (перебивать Джони во время ответа).

## Архитектура

### Новый модуль `johnny/audio.py`

```
Microphone
    sd.RawInputStream(16000 Гц, int16, моно, blocksize=4000 = 0.25с)
        callback → очередь блоков (с потолком, чтобы не пухла в памяти)
    read_block(timeout=2.0) → блок; попутно кладёт его в кольцо
                              по таймауту бросает MicrophoneError
    preroll()               → снимок последних 1.5с (не очищает)
    flush()                 → выбросить очередь И кольцо
    контекстный менеджер: открывает/закрывает устройство
```

Блок 0.25с вместо нынешних 0.5с у Vosk — реакция на имя вдвое быстрее.
Меньше не берём: на 0.25с уже настроен RMS-порог тишины `0.01` в
существующем рекордере, и трогать оттестированное значение незачем.

Рядом — две функции без состояния:

- `to_float32(raw)` — int16 → float32 для Whisper.
- `record_until_silence(mic, max_seconds, silence_seconds, start_timeout)`
  → `(аудио, заговорил_ли)`. Переезжает из `Recognizer._record_until_silence`
  почти без изменений; новое — второй элемент кортежа, флаг «речь вообще
  началась».

`MicrophoneError` нужен потому, что с постоянным потоком меняется характер
отказа микрофона. Сегодня «микрофон отключили» — исключение в конструкторе
потока, и счётчик подряд идущих сбоев в `AssistantController.run` его ловит.
С постоянным потоком callback просто перестаёт срабатывать, и без таймаута
`read_block()` завис бы навсегда. С таймаутом существующая защита (пауза 1с,
стоп после 5 сбоев подряд) продолжает работать как задумано.

### Цикл в `AssistantController`

```
listener.wait_for_wake_word(mic)      ← Vosk читает блоки из общего микрофона
       ↓ поймал «джони»
preroll = mic.preroll()               ← 1.5с назад: там имя и пауза до него
хвост, заговорил = record_until_silence(mic, start_timeout=0.75с)
       ↓
  заговорил? ──да──→ СЛИТНО: transcribe(preroll + хвост), звука не было
       │
       нет
       ↓
       ПАУЗА: acknowledge() → mic.flush() → record_until_silence(start_timeout=6с)
```

Порог паузы — 0.75с. Пользователь выбрал 0.7с; на сетке блоков 0.25с
округляем **вверх**, потому что 0.7 выбрано именно чтобы Джони не перебивал
звуком естественный зазор внутри фразы, и округление вниз (0.5с) сломало бы
смысл выбора.

`mic.flush()` после ack-звука обязателен, иначе Джони запишет собственный
«пик». По той же причине flush идёт в конце цикла, после любого ответа TTS:
произнеся вслух ответ модели со словом «Джони», Джони разбудил бы сам себя.
Сегодня это невозможно физически (поток закрыт), с постоянным потоком —
реальный сценарий. Всё воспроизведение синхронное (`play ... wait` в MCI,
`sd.wait()` в бипе), поэтому одного flush достаточно, гонок нет.

Микрофон остаётся открытым и на паузе трея: цикл по-прежнему ловит вейкворд
и выходит раньше, поведение паузы не меняется.

## Имя как якорь

`strip_wake_word(text, variants) -> (текст_без_имени, найдено)` — чистая
функция в `listener.py`, рядом со знанием о вариантах имени.

```
strip_wake_word("эй джони громкость пять", ["джони","джонни","джани"])
    → ("громкость пять", True)
```

- Работает по нормализованному тексту (нижний регистр, ё→е — та же
  нормализация, что в роутере).
- Ищет нечёткое совпадение (`difflib`, порог 0.75) — ловятся «Джонни»,
  «Джани», «Джонни,».
- Ищет **только в первых трёх словах**: дальше случайное созвучие срезало бы
  всю команду.
- Режет **до последнего** совпадения в этих трёх словах: пре-ролл иногда
  захватит хвост предыдущей речи, и «...ага, джони, громкость пять» должно
  дать `громкость пять`.

Чтобы `найдено` было надёжным, имя добавляется в шапку подсказки Whisper:
`_BASE_PROMPT = "Русские голосовые команды. Джони."` Это стоит около трёх
токенов из бюджета 224, то есть словарь имён сокращается на одно слово
(`_MAX_VOCAB_WORDS` пересчитывается реальным токенизатором, как в прошлой
итерации). Фильтр `is_prompt_echo` берёт длину шапки из самого prompt и
подстраивается автоматически.

### Доверие к срабатыванию

Vosk small услышал имя, а Whisper medium на той же записи его не видит →
скорее всего Vosk ошибся. Выбрасывать такое молча нельзя (Whisper мог
проглотить быстрое тихое «Джони», а потерять настоящую команду хуже, чем
выполнить лишнюю), поэтому доверие понижается, а не обнуляется:

| Рубеж | имя найдено | имя не найдено |
|---|---|---|
| точное совпадение | выполняем | выполняем |
| шаблонный fuzzy (0.72) | выполняем | выполняем |
| модель-корректор (Groq/Claude) | спрашиваем | **не спрашиваем** |
| ничего не сошлось | звук + ждём команду | молчим + история |

Модель отрезается там, где она опаснее всего: её работа — превратить
невнятицу в ближайшую команду, и на случайной болтовне из войсчата она это
честно сделает. Плюс ложное срабатывание перестаёт стоить обращения к API.

Защиту опасных команд это не ослабляет: `router.is_unsafe_action` по-прежнему
требует точного совпадения на всех рубежах.

### Восстановление

Если имя найдено (значит вейкворд подтверждён двумя движками — пользователь
действительно звал), но команда после него ни во что не сошлась, Джони
падает в обычную ветку с паузой: играет звук и ждёт команду. Молчание в этом
случае ощущалось бы как «не услышал», хотя он услышал.

Восстановление — это буквально та же ветка с паузой (общий код), поэтому
дальше всё как при осознанном вызове: провал озвучивается («Не расслышал»),
модель-корректор доступен. Попытка ровно одна за цикл — второго
восстановления из восстановления нет. В историю пишется одна строка, по
итогу восстановления, с обычной пометкой без приставки `слитно/`.

Побочная польза: это полностью снимает риск шумного фона. Решение «слитно
или пауза» держится на RMS-пороге `0.01`; если фон окажется громче порога,
Джони всегда будет считать, что речь продолжается, и звук-подтверждения не
сыграл бы никогда. С восстановлением такой случай сам сваливается в
двухтактный режим: текст после имени пустой → звук → ждём команду.

### Режим с паузой не меняется

Там имени в записи нет по построению (запись начинается после звука), поэтому
и проверять нечего: полная лестница, и Джони говорит «Не расслышал» / «Не
понял команду», как сегодня. Пользователь позвал осознанно — Джони обязан
ответить.

## Интерфейс `handle_command`

```python
handle_command(text, config, speaker, *, speak_failures=True, use_brain=True) -> Outcome
```

- `speak_failures` управляет **только** семейством «не понял»: «Не расслышал»,
  «Не понял команду». Сбои выполнения («Не знаю такой программы», «Не смог
  выполнить команду») озвучиваются всегда — команда была понята.
- `use_brain=False` пропускает обращение к модели-корректору.
- `Outcome(via: str, handled: bool)` вместо нынешней голой строки `via`.
  `handled=False` ровно для семейства «не понял» — по нему контроллер решает,
  запускать ли восстановление.

Значения по умолчанию воспроизводят сегодняшнее поведение, поэтому
существующие вызовы и тесты `test_app.py` (они проверяют реплики, а не
возвращаемое значение) остаются валидными.

## История

`via` получает приставку, чтобы ложные срабатывания было видно глазами:

```
14:22:01  громкость пять        слитно/точно
14:22:40  громкость пять        точно                  ← режим с паузой
14:31:07  да я говорю ему       слитно(без имени)/мимо  ← Vosk ошибся, Джони промолчал
14:35:12  поставь на пузу       слитно/похоже (0.79)
```

В историю пишется текст **после** отрезания имени — тот, который уходил в
роутер: именно на нём настраиваются пороги.

## Изменения по файлам

| Файл | Что меняется |
|---|---|
| `johnny/audio.py` | новый: `Microphone`, `MicrophoneError`, `to_float32`, `record_until_silence` |
| `johnny/listener.py` | `wait_for_wake_word(mic)`; свой поток, очередь и callback уходят; **перестаёт чистить хвост очереди** — это ровно тот звук, за которым мы пришли, сбрасывается только состояние Vosk; публичное `wake_words`; чистая `strip_wake_word` |
| `johnny/recognizer.py` | `_record_until_silence` уезжает в `audio.py`; `listen_command()` → `transcribe(audio)`; имя в `_BASE_PROMPT` |
| `johnny/controller.py` | две ветки, `mic` третьим аргументом, восстановление, `flush()` после ack и в конце цикла |
| `johnny/app.py` | новые флаги и `Outcome` у `handle_command`; `run()` идёт через `AssistantController` вместо своего цикла |
| `johnny/tray.py` | создаёт `Microphone`, прокидывает в `controller.run`, закрывает на выходе |

`run()` переводится на контроллер не ради красоты: иначе двухрежимную логику
пришлось бы написать дважды, и две копии неизбежно разъедутся. Заодно
консольный вход получает обёртку try/except вокруг цикла — известная мелочь
из списка «на будущее».

Пороги — константы модуля с комментарием-обоснованием, как принято в проекте:
пре-ролл 1.5с, порог паузы 0.75с, таймаут блока 2с. `settings.yaml` не
трогаем.

## Живая проверка (нужен настоящий микрофон, только пользователь)

1. Слитно: «Джони громкость пять» — звука-подтверждения быть не должно,
   громкость меняется.
2. С паузой: «Джони» → пауза → звук → «громкость пять» — как раньше.
3. Восстановление: «Джони» + невнятица слитно → должен прозвучать звук и
   Джони должен ждать команду.
4. Самопробуждение: задать вопрос, в ответе на который прозвучит слово
   «Джони», убедиться, что он не разбудил сам себя.

## Осознанно не делаем

- Перебивать Джони во время ответа (barge-in по TTS) — отдельная задача,
  общий микрофонный поток её разблокирует, но в этот объём не входит.
- Настройки порогов в `settings.yaml` — пока константы кода.
- Вейкворд Vosk small → full: остаётся в отложенных, хотя точность
  срабатывания теперь частично компенсируется проверкой имени через Whisper.
