# Управление Discord голосом

Дата: 2026-07-28

## Чего хочет человек

Две команды, и обе — для случая «за компьютером ещё толком не сижу»:

- **«Позвони Гоше»** — начать голосовой звонок в личные сообщения.
- **«Напиши Гоше ...»** — отправить сообщение, потому что надиктовать быстрее, чем печатать.

Мьют, «оглохнуть» и демонстрация экрана **в работу не берутся**: человек делает их горячими клавишами Discord, и так быстрее любого голоса. Заводить под них команды — значит платить за то, что уже работает лучше.

## Почему десктоп, а не браузер

Первоначально планировался разрез «сообщения через браузер, звонки через десктоп». Пробник его отменил — и хорошо.

Голос физически живёт в одном клиенте: заход в голос из браузера выкидывает десктоп из канала. Значит звонок из браузера означал бы, что индивидуальная громкость участников, оверлей и привычные хоткеи перестают относиться к разговору. Для сообщений это ограничение не действует (текст есть текст), поэтому браузер оставался кандидатом на половину задачи.

Но пробник показал, что **десктоп умеет всё сам**. Раз так, браузер отпадает целиком: не нужен ни отдельный логин, ни второй клиент, ни синхронизация состояния между ними. Джони работает ровно в том Discord, в котором сидит человек.

## Что показал пробник

Замеры на живом клиенте (`uiautomation` 2.0.29, окно `@Гречка - Discord`):

| Что проверяли | Результат |
|---|---|
| Дерево доступности читается | **Да**, 253 элемента |
| Полный обход дерева | **1.4 с** |
| Дерево у свёрнутого окна | **Пусто**, 0 элементов |
| Первый запрос дерева | Возвращает 0 — доступность включается лениво |

### Имена элементов (проверены, не угаданы)

```
[ButtonControl]    Начать голосовой звонок
[ButtonControl]    Начать видеозвонок
[HyperlinkControl] Грущенко (личное сообщение)
[HyperlinkControl] uHcTuHKT (Олег) (личное сообщение)
[EditControl]      Написать @Гречка
[ButtonControl]    Найти или начать беседу
```

### Три ловушки, найденные пробником

**1. Окно ищется по процессу, а не по заголовку.** Первая версия пробника нашла окно терминала, у которого в заголовке вкладки стояло слово «Discord». Искать надо по `discord.exe` через `GetWindowThreadProcessId` + `GetModuleFileNameEx`.

**2. Доступность просыпается лениво.** Chromium не строит дерево, пока его никто не спросил. Первый обход вернул 0 элементов, второй — 253. Значит запрашивать надо дважды: первый вызов будит, второй читает.

**3. У свёрнутого окна дерева нет вообще.** Не «мало элементов», а ровно ноль: свёрнутое окно Chromium считает невидимым и дерево не отдаёт. Перед работой окно обязано быть развёрнуто.

## Архитектура

```
config/people.yaml     алиасы: как человек зовёт → как подписан в Discord
johnny/discord_ui.py   работа с деревом: найти окно, разбудить, найти, нажать
johnny/keyboard.py     печать текста через SendInput
johnny/actions.py      discord_call / discord_message + ветки execute
config/commands.yaml   «позвони *», «напиши *»
johnny/router.py       «позвони» попадает в разряд неугадываемых
```

Границы такие: `discord_ui.py` ничего не знает про команды и алиасы — он умеет только «найди в дереве элемент с таким именем и нажми». `actions.py` ничего не знает про UI Automation — он переводит произнесённое имя в имя элемента. Проверять их можно порознь: первый на живом Discord, второй на моках.

### `johnny/discord_ui.py`

```python
def window()                       # hwnd окна discord.exe; None, если не запущен
def tree(hwnd)                     # элементы дерева; будит доступность и читает со второй попытки
def find(hwnd, kind, predicate)    # первый подходящий элемент
def invoke(element) -> bool        # нажатие паттерном Invoke, без мыши
def ensure_visible(hwnd) -> bool   # развернуть окно; вернуть, было ли оно свёрнуто
def restore_state(hwnd, was_minimized)
```

Нажимаем **паттерном Invoke, а не мышью**. `uiautomation` умеет `.Click()`, но он двигает настоящий курсор — Джони выдёргивал бы мышь из-под руки посреди игры.

### `config/people.yaml`

Формат повторяет уже существующий `channels.yaml`:

```yaml
гоша:
  discord: "Грущенко"
  aliases: ["гоша", "гошан"]
олег:
  discord: "uHcTuHKT (Олег)"
  aliases: ["олег", "инстинкт"]
```

`discord:` — подстрока имени в дереве, а не точное совпадение: рядом с именем Discord дописывает статус («не прочитано», «Не беспокоить»), и эта приписка меняется сама по себе.

Падежи достаются бесплатно: `_stem_phrase` из `actions.py:117` уже приводит «Гоше» и «Гошу» к «гош» — тот же механизм, что работает для каналов Твича.

### Разбор фразы

Оба шаблона — с **одной** звёздочкой, и это осознанно. Роутер умеет нечёткое совпадение только для шаблонов с одним слотом (`_split_pattern`, `router.py:115`), а на «напиши * *» пришлось бы полагаться на точное совпадение и терять команду каждый раз, когда Whisper услышит «напишы».

Поэтому весь хвост попадает в один аргумент, а имя отделяется внутри действия — **по самому длинному совпавшему алиасу**:

```
«гоша привет как дела»       → («гоша», «привет как дела»)
«дядя вася ты где»           → («дядя вася», «ты где»)   если алиас двусловный
```

Жадный разбор по первому слову сломался бы на двусловных именах, поэтому берём длиннейший префикс, совпавший с алиасом.

### Что происходит по команде

**«Позвони Гоше»**

1. Найти окно `discord.exe`. Нет — «Discord не запущен».
2. Развернуть окно, если свёрнуто (запомнив, что оно было свёрнуто).
3. Разбудить и прочитать дерево.
4. Найти ссылку, имя которой содержит `(личное сообщение)` и совпадает с алиасом. Не нашли — «Не нашёл Гошу в личных сообщениях».
5. Invoke по ссылке, дождаться появления шапки переписки.
6. Найти кнопку `Начать голосовой звонок`, Invoke.
7. Окно **оставить развёрнутым**: идёт звонок, его надо видеть.

**«Напиши Гоше привет»**

Шаги 1–5 те же, дальше:

6. Найти поле ввода, имя которого начинается с `Написать @`.
7. **Сверить адресата.** Имя поля содержит того, кому пишем, — `Написать @Гречка`. Если оно не совпадает с запрошенным человеком, ничего не печатать и вернуть отказ.
8. Поставить фокус, напечатать текст, Enter.
9. Если окно было свёрнуто до команды — свернуть обратно.

Шаг 7 — главная защита этой спеки. Она не «мы аккуратно написали код, поэтому не промахнёмся», а проверка по факту, прямо перед вводом: сообщение не может уйти не в тот чат молча.

### Печать текста

`EditControl` в Chromium — это `contenteditable`, и `ValuePattern.SetValue` на нём может не поддерживаться. Поэтому основной способ — фокус плюс печать через `SendInput` с юникодными символами (`johnny/keyboard.py`), а `SetValue` пробуется первым только как быстрый путь.

Этот же модуль потом бесплатно закроет отдельную хотелку — команду «Ввод \*», печать надиктованного в любое активное поле. В эту спеку она **не входит**, но `keyboard.py` проектируется так, чтобы она свелась к одной новой ветке в `execute`.

### Неугадываемость звонка

`router.is_unsafe_action` (`router.py:31`) — единственное место в проекте, где определяется «такое угадывать нельзя»; его же спрашивает brain, чтобы модель не протащила действие в обход. Туда добавляется `discord_call`.

Следствие: «позвони» должно быть услышано **точно**. Это осознанный размен — «позвони Гоше» не должно вылетать из «покажи Гошу» по похожести 0.83. Слово «позвони» короткое и частотное, Whisper на нём стабилен, а в словарь подсказки оно попадёт автоматически (`build_vocabulary` берёт значимые слова шаблонов).

Отправка сообщения **остаётся угадываемой**, и это тоже размен, но в другую сторону: команда нужна именно тогда, когда говорят на ходу, и терять её на «напишы» нельзя. Прикрытие у неё другое — сверка адресата на шаге 7 и озвучка отправленного постфактум («Отправил Гоше: привет»), чтобы ошибка была слышна сразу.

## Пауза только когда Whisper не уверен

Отдельный, отделяемый кусок. Человек выбрал «отправлять сразу», но спросил, нельзя ли пожертвовать парой секунд ради точности, когда распознавание плохое.

Можно, и точнее, чем «ждать всегда»: `recognizer.transcribe` (`recognizer.py:148`) уже получает от Whisper сегменты с метрикой `avg_logprob` и **выбрасывает их**. Достаточно вернуть уверенность наружу.

Тогда при уверенности ниже порога Джони на команду сообщения **не переспрашивает, а отказывается**: «не расслышал, повтори». Это важное упрощение — диалога «да/нет» в проекте нет, и строить машину состояний ради этого не нужно. Человек просто повторяет фразу целиком, и платит за это только в тех случаях, когда Whisper и правда услышал плохо.

Порог подбирается по живым данным, поэтому кусок ставится последним: сначала уверенность просто пишется в `history.log` рядом с распознанным текстом, потом по накопленному выбирается число.

Этот кусок **не блокирует** остальные: без него сообщения работают ровно так, как человек и просил — сразу.

## Что осталось непроверенным

Пробник читал дерево, но ничего не нажимал, поэтому проверке на живом клиенте подлежат:

1. **Работает ли Invoke** на этих кнопках. Читаемость дерева не гарантирует, что кнопка поддерживает нажатие программно; запасной путь — координатный клик по `BoundingRectangle` элемента.
2. **Принимает ли поле ввода `SetValue`** или нужна печать клавишами.
3. **Человека нет в списке личных сообщений.** Боковой список показывает только недавние переписки. Запасной путь — кнопка `Найти или начать беседу` (`Ctrl+K`), ввод имени, Enter.
4. **Не засыпает ли доступность обратно** между командами. Если засыпает — пробуждение делается перед каждой командой, а не один раз.

Все четыре проверяются на живом Discord и **только с явного разрешения человека** — это его условие с самого начала разговора, и оно относится ко всему, что нажимает кнопки, а не только к звонкам.

## Тестирование

`discord_ui.py` отделён от `actions.py` именно ради этого:

- **На моках** (обычный pytest, как `tests/test_browser.py`): разбор фразы на имя и текст, поиск алиаса по падежам, сверка адресата, поведение при ненайденном человеке, восстановление свёрнутого окна.
- **На живом Discord** (вручную, с разрешения): чтение дерева, Invoke, реальная отправка сообщения себе, и последним — звонок.

Первый живой тест отправки делается **в переписку с самим собой**, а не живому человеку.

## Порядок работ

1. `johnny/discord_ui.py` + `johnny/keyboard.py` — фундамент, проверяется чтением.
2. `people.yaml`, разбор фразы, `discord_message` — сообщения целиком.
3. `discord_call` + `is_unsafe_action` — звонки.
4. Уверенность распознавания — по накопленным данным.

Звонки идут после сообщений сознательно: у сообщения ошибка исправляется удалением, у звонка — нет.

## Чего эта спека НЕ делает

- Не трогает мьют, «оглохнуть» и демонстрацию экрана — они остаются на горячих клавишах.
- Не вводит команду «Ввод \*» — она получает фундамент (`keyboard.py`), но остаётся отдельной задачей.
- Не работает с серверными голосовыми каналами — только личные сообщения.
- Не читает входящие сообщения и не отвечает на входящие звонки.
