# Память, диктовка и живая история

Дата: 2026-08-06

## Задача

Четыре независимых доработки, запрошенные одним заходом:

1. **«напечатай» как алиас** для команды ввода текста — сейчас работают только «ввод»/«вводи»/«введи» (изначально просили «напиши», но это слово уже занято под Discord-сообщения, см. ниже).
2. **Баг «vd»**: Whisper иногда транскрибирует активатор «Джони» латинским мусором вместо кириллицы, и этот мусор остаётся приклеенным к началу распознанной фразы.
3. **Живая история команд**: пункт трея «История команд» сейчас открывает `history.log` в Notepad — статичный снимок, чтобы увидеть новые строки, нужно закрыть и открыть заново.
4. **Память**: Джони не помнит ничего между репликами и между запусками. Главный сценарий: Джони спросил «Хотите X?» в разговорном ответе, пользователь говорит «Джони, да, давай, расскажи» — сейчас это отдельная, ничем не связанная с прошлым команда.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Порядок работы | Всё четыре в одной итерации | По прямому решению пользователя |
| Способ восстановления «vd» | Эвристика по скрипту (латиница/кириллица), без привязки к конкретному слову | Живые данные показали: единой замены слова нет, это общий артефакт распознавания активатора |
| Какая память нужнее | Короткая память разговора (3-5 обменов, 10 минут) — приоритет; долгосрочные факты — только явной командой | Пользователь явно расставил приоритеты в обсуждении |
| Автоизвлечение фактов без команды | НЕ делаем в этой итерации | Риск: ASR у проекта местами шумный (те же баги, что чинили сегодня) — тихое сохранение потенциально искажённых фактов труднее заметить и почистить, чем не делать вовсе |
| Как показывать «что ты помнишь» | Озвучивать целиком | Голосовой ассистент — голосом естественнее, чем открывать файл |
| Живая история — реализация | Отдельное Tk-окно с тейлом файла, не Notepad | Notepad не умеет сам обновляться; менять его не на что стороннее — пишем маленькое своё окно |

## Раздел 1 — «напечатай» + баг «vd»

### «напечатай»

Изначальная просьба была «напиши», но `"напиши *"` уже занято под Discord-сообщения (`config/commands.yaml:571`, action `discord_message`, «напиши Стасу привет») — оба смысла свободный текст после глагола, шаблонами не различить. Решение пользователя: не трогать Discord, для ввода текста завести отдельное слово «напечатай».

`config/commands.yaml`, рядом с существующими `"ввод *"`/`"вводи *"`/`"введи *"`:

```yaml
"напечатай *":
  action: type_text
  template: "{0}"
```

### Баг «vd»

Разбор живых логов (`history.log`, 8 случаев за 2026-08-04..06) показал общий паттерн: короткий (1–4 буквы) латинский токен строго первым словом фразы, за ним — связный русский текст. Ни разу мусорный токен не был осмысленным словом ни на одном из языков. Это тот же класс бага, что чинили 2026-07-28 (`recover_misheard_name`): Whisper не теряет активатор, а подменяет его — но в этих случаях подмена настолько далека фонетически («vd» vs «джони»), что не проходит даже мягкий fuzzy-порог, а сама фраза чаще всего разговорная (не команда), поэтому имеющийся `recover_misheard_name` (который требует, чтобы остаток был точной командой) не срабатывает.

Новая функция в `johnny/listener.py`:

```python
def recover_latin_prefix(text: str) -> str | None:
    """Первое слово — короткий латинский мусор, дальше — кириллица?
    Тот же класс бага, что recover_misheard_name, но без требования, что
    остаток — команда (годится и для разговорных фраз к модели)."""
```

Логика: первое слово соответствует `^[a-z]{1,4}$` (после нормализации `_words`, т.е. без пунктуации) И среди оставшихся слов есть хотя бы одно кириллическое — тогда отрезаем первое слово. Иначе `None`.

**Известная цена (принята осознанно):** если Whisper теряет активатор, а следующее ЗА НИМ настоящее слово команды само оказывается коротким и латиницей (например, «Джони, obs завис» расслышано как «obs завис»), эвристика отрежет его как мусор и потеряет часть смысла. `recover_misheard_name` проверяется первым и не спасает такой случай (короткий остаток «завис» не резолвится в команду), так что риск реален, но узок: короткие латинские слова в начале фразы у этого пользователя — либо игры/программы (уже слышны и до этой фразы, среди первых 3 слов проверяет `strip_wake_word`), либо, по факту живых логов, всегда были мусором. Если станет заметной проблемой на практике — сузить эвристику (например, требовать конкретный список подтверждённых мусорных токенов вместо любого короткого латинского слова).

Место включения — `controller._joined_turn`, как ВТОРОЙ, более широкий рубеж восстановления имени, сразу после того, как `recover_misheard_name` не сработал:

```python
recovered = recover_misheard_name(text, self.config.commands)
if recovered is not None:
    text, found = recovered, True
    mark = "слитно(имя восстановлено)"
else:
    latin_recovered = listener.recover_latin_prefix(text)
    if latin_recovered is not None:
        text, found = latin_recovered, True
        mark = "слитно(имя восстановлено: латиница)"
```

Отдельная пометка в истории (`латиница`) — чтобы при следующей жалобе на распознавание было видно из лога, какой из двух механизмов сработал, не гадая.

## Раздел 2 — Живая история команд

Новый модуль `johnny/history_viewer.py`:

- `open_or_focus(history_path: Path) -> None` — публичная точка входа для трея. Если окно с фиксированным заголовком («Джони — история команд») уже существует (`win32gui.FindWindow`, тот же приём, что `browser.bring_to_front`), поднимает его на передний план. Иначе поднимает новый поток с Tk-окном.
- Окно: `tkinter.Text` в режиме только для чтения внутри `tkinter.Toplevel`/`Tk`, читает файл целиком при открытии, дальше каждые 0.5с (`root.after`) проверяет размер файла — если вырос, дочитывает добавленный хвост и вставляет в конец виджета + автоскролл. Закрывается обычным крестиком (стандартный `WM_DELETE_WINDOW`, поток завершается вместе с `mainloop()`).
- Чтение «нового хвоста файла по последнему известному размеру» — чистая функция без Tk (`_read_new_tail(path, last_size) -> tuple[str, int]`), тестируется юнит-тестом отдельно от GUI-части (GUI-часть, как и остальной `tray.py`, юнит-тестами не покрывается).
- `johnny/tray.py`: пункт «История команд» переключается с `os.startfile` на `history_viewer.open_or_focus(_HISTORY)`.

## Раздел 3 — Память

Новый модуль `johnny/memory.py`, две независимые части.

### Короткая память разговора

```python
@dataclass
class Turn:
    user_text: str
    reply: str
    at: float  # time.monotonic()
```

Модульное состояние (как `actions._duck_active`) — процесс один (`single_instance`), поэтому глобальный `deque(maxlen=5)` достаточен, не нужно протаскивать объект через весь стек вызовов:

- `record_turn(user_text: str, reply: str) -> None` — добавляет обмен.
- `recent_context(max_age: float = 600.0) -> list[Turn]` — отдаёт обмены не старше `max_age` секунд от текущего момента. Не переживает перезапуск процесса (не нужно — это контекст живого разговора).

### Долгосрочные факты

Файл `memory.yaml` в корне проекта (в `.gitignore`, как `history.log`), формат:

```yaml
- text: "У пользователя друг Артём играет на аккаунте..."
  added: "2026-08-06 15:20:00"
```

- `remember(text: str) -> None` — добавляет факт, пишет файл.
- `forget(query: str) -> str | None` — ближайший факт по ДОЛЕ СЛОВ запроса, найденных внутри текста факта (не `difflib.SequenceMatcher` по целым строкам — измерено на примере: «забудь про стим» против факта «у пользователя стим-аккаунт art_vol_teror» даёт всего 0.45 посимвольной похожести, ниже любого разумного порога, потому что короткий запрос и длинный факт сильно отличаются по длине; при этом оба слова запроса «стим»/«аккаунт» буквально есть в тексте факта). Считаем: `слова_запроса ∩ слова_факта / слова_запроса`; если у лучшего факта доля ≥ **0.5** — удаляет и возвращает удалённый текст, иначе `None`.
- `list_facts() -> list[str]` — все факты как есть, в порядке добавления.

### Подключение в `brain.py`

`_PROMPT` получает необязательный блок в начале (пустая строка, если нечего показать):

```
{memory_block}
```

где `memory_block` — сериализация короткой памяти («Недавний разговор: ты спросил ... / пользователь ответил ...») и списка фактов («Известно о пользователе: ...»), собранные ДО вызова `interpret`.

`interpret()` получает новый необязательный параметр `memory_block: str = ""`, подставляемый в `_PROMPT.format(...)`. Функция остаётся чистой (сборка блока — снаружи, в `app.py`), чтобы `brain.py` не тянул модуль `memory` напрямую и оставался тестируемым тем же способом, что сейчас (передача произвольной строки).

`app.py::handle_command`, шаг 4 («Модель»): перед вызовом `interpret` собирает `memory_block` из `memory.recent_context()` + `memory.list_facts()`; после получения `answer` — вызывает `memory.record_turn(text, answer.reply or "")`, если `answer is not None`. Только этот путь (LLM опрошен) пишет в короткую память — обычные локальные команды (точное/нечёткое совпадение без модели) в неё не попадают, они не порождают контекст, на который может ссылаться «да, давай».

### Новые действия

`config/commands.yaml`:

```yaml
"запомни *":
  action: remember
  template: "{0}"
"забудь *":
  action: forget
  template: "{0}"
"что ты помнишь":
  action: list_memory
  template: "-"
"что ты помнишь обо мне":
  action: list_memory
  template: "-"
```

`johnny/actions.py::execute` — три новые ветки:

- `remember`: `memory.remember(argument)` → `ActionResult(True, "Запомнил")`.
- `forget`: `memory.forget(argument)` → `ActionResult(True, "Забыл")` если что-то удалено, иначе `ActionResult(False, "Не нашёл такое в памяти")`.
- `list_memory`: собирает `ActionResult(True, "<список фактов через '; ' или 'Я пока ничего не помню'>")`.

**Важная деталь по озвучке `list_memory`**: обычный путь `_respond` при успехе (`result.ok=True`) сперва пытается сыграть короткий звук (`speaker.play_answer()`) и озвучивает текст только запасным путём, если звука нет — факты в таком виде почти никогда не будут произнесены. Для `list_memory` это исключение: `app.py::_dispatch` получает точечную проверку (по образцу уже существующей `_punctuate_dictation`) — для этого действия текст `result.message` озвучивается всегда, минуя `play_answer()`.

## Тестирование

- `listener.recover_latin_prefix` — юнит-тесты на реальных строках из `history.log` (8 живых случаев) + контрольные «не трогать», где короткое латинское слово легитимно (например, реальная команда на английском).
- `memory.py` — `record_turn`/`recent_context` (включая истечение 10 минут через монки-патч времени), `remember`/`forget`/`list_facts` (включая нечёткий `forget`, включая случай «не нашёл»).
- `history_viewer._read_new_tail` — чистая функция, без Tk.
- `actions.execute` — три новые ветки (по образцу существующих тестов для `type_text`/`press_enter`).
- `app._dispatch` — принудительная озвучка `list_memory` вместо чиркающего звука.
- `commands.yaml` — регрессия «все команды файла резолвятся» (существующий тест) должна пройти и с тремя новыми строками.
