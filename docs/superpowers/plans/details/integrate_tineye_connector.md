## Integrate TinEye reverse-image search connector

Цель: Позволить выполнять обратный поиск изображений через TinEye API и кешировать результаты.

Критерии успеха:
- Реализован запрос к API TinEye и сохранение метаданных результата.
- Результаты доступны в UI и могут быть связаны с источниками сообщений.

Шаги:
1. Ознакомиться с TinEye API и ограничениями.
2. Реализовать адаптер с кэшированием и rate-limit handling.
3. Интегрировать с pipeline аналитики изображений.

Зависимости: TinEye API key

---

### ЗАМЕНЕНО: вместо TinEye — Azure AI Vision

Решение владельца: TinEye заменён на
[Azure AI Vision](https://azure.microsoft.com/en-us/products/ai-foundry/tools/vision).
Коннектор — `johnny/connectors/azure_vision.py`, тесты —
`tests/test_azure_vision_connector.py`, описание — `docs/connectors.md`.

**Цель этого пункта закрыта НЕ полностью, и это надо читать буквально.** TinEye
отвечал на вопрос о происхождении: «где ещё в интернете встречается эта
картинка». Azure отвечает на другой: «что на этой картинке изображено и что на
ней написано». Поиска по индексу интернета у Azure нет вовсе — тот, что был у
Microsoft (Bing Visual Search), закрыт.

Значит обратный поиск картинки не выполняет ни один наш коннектор. Фразы «откуда
эта картинка» и «проверь картинку» убраны из `config/commands.yaml`, а тест
падает, если действие `reverse_image` вернётся: команда, которая обещает то, чего
нет, хуже отсутствующей.

Что получено взамен: OCR и распознавание объектов, то есть соседний пункт плана
(`add_ocr_and_live_camera_recognition_support.md`). Кеш по содержимому файла,
суточная квота, согласие — общие требования плана выполнены слоем `base.py`,
согласие здесь обязательно: уходит файл с этого компьютера, а не публичная
ссылка.

### Пункт НЕ закрыт: TinEye, возможно, придётся вернуть

Вопрос о происхождении картинки остался без исполнителя. Если он понадобится,
вернуть придётся именно TinEye — аналога у Azure нет и не появится.

Возврат недорог: `base.py` не менялся, вся политика (согласие, кеш, квота, пауза
между вызовами, офлайн-отказ) живёт в нём, коннектору остаются `available()` и
`_run()`. Само тело `_run` — POST на `https://api.tineye.com/rest/search/` с
ключом, ответ сжимается до доменов и самой ранней даты обхода; тело ответа в лог
класть нельзя, TinEye возвращает эхом запрос вместе с ключом.

Вернуть надо не только файл коннектора, иначе он недосягаем:

- `config/commands.yaml` — фразы «откуда эта картинка \*», «проверь картинку \*»
  (выше хвостового `открой *`, иначе жадный шаблон заберёт фразу себе);
- `johnny/actions/connector_action.py` — действие `reverse_image`;
- `johnny/connectors/factory.py` — строка в `BUILDERS`;
- `config/secrets.yaml.example` — `tineye_api_key`;
- `johnny/panel_tools.py` — карточка в панели.

И один сторож: `tests/test_connector_actions.py::test_removed_phrases_are_gone_from_commands`
падает, если `reverse_image` вернётся. Это напоминание, а не препятствие — тест
снимается тем же решением, которым возвращается команда.

Заменять Azure обратно не нужно: вопросы разные. TinEye не скажет, что на
картинке написано, Azure не скажет, где эта картинка встречается. Держать оба —
нормально, лишний ключ ничего не стоит, пока согласие выключено.

Приватность/безопасность: не запрашивать приватные изображения без согласия

Оценка: 2-4 дней
