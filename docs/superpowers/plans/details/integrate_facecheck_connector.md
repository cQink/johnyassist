## Integrate FaceCheck.ID face-recognition connector with consent/moderation

Цель: Добавить возможность поиска лиц и соответствия через FaceCheck.ID с обязательными политиками согласия.

Критерии успеха:
- Есть адаптер к FaceCheck.ID и UI для отображения совпадений.
- Система требует явного согласия перед анализом лиц.

Шаги:
1. Изучить API FaceCheck.ID и правила использования.
2. Реализовать адаптер с логикой согласия и модерацией.
3. Интегрировать отключаемую опцию в настройки приватности.

Зависимости: FaceCheck.ID API, правовые требования

Приватность/безопасность: обязательное согласие, логирование доступа

Оценка: 3-6 дней

---

### ЗАМЕНЕНО: вместо FaceCheck.ID — Face++

Решение владельца: FaceCheck.ID заменён на
[Face++](https://www.faceplusplus.com/). Коннектор —
`johnny/connectors/faceplusplus.py`, тесты —
`tests/test_faceplusplus_connector.py`, описание — `docs/connectors.md`.

**Подмена здесь существеннее, чем у картинок.** FaceCheck искал лицо ПО ВСЕМУ
ИНТЕРНЕТУ — то есть отвечал «кто этот человек и где он засветился». Face++ по
сети не ходит вообще: он сравнивает ровно те два снимка, которые ему дали
(`/compare`), и разбирает лицо в кадре (`/detect`). Поиска человека по лицу
больше нет ни у одного нашего коннектора, фраза «найди это лицо» убрана из
`config/commands.yaml`, и тест падает, если действие `face_search` вернётся.

Требования приватности из этого файла выполнены целиком и остались обязательными,
потому что лицо всё равно уезжает третьей стороне — биометрия остаётся
биометрией:

- Согласие обязательно (`requires_consent = True`), без него не уходит ни байта и
  в журнал не пишется ни строки.
- Журнал доступа рядом с кешем: время, режим, имя файла, короткий хеш, число лиц.
  Ни снимка, ни признаков лица — журнал отвечает на «чьи лица и когда мы
  отправляли», а не хранит их. Сломанный журнал не стоит человеку ответа.
- Пол (`gender`) не запрашивается вовсе: сервис отдаёт его как выбор из двух, ни
  одной команде он не нужен, а ошибка в нём — ошибка про живого человека.
- 83 точки разметки лица выбрасываются до кеша.
- Ключ и секрет уходят полями формы, а не в строке запроса: строку запроса пишет
  в свой лог любой прокси по пути.
- Вердикт «тот же человек» считается по порогу из самого ответа и по самому
  строгому из трёх (1e-5); порог всегда произносится рядом со сходством. Мутный
  кадр отмечается отдельно — по нему сравнение уверенно говорит «не тот человек».

Модерация из шага 2 сведена к этому набору сознательно: своей модели «уместно ли
это сравнение» у нас нет, а имитация её проверкой по списку слов давала бы ложное
чувство защиты. Роль ограничителя играют согласие, журнал и суточная квота.

### Пункт НЕ закрыт: FaceCheck.ID, возможно, придётся вернуть

Вопрос «кто этот человек и где он засветился» остался без исполнителя. Если он
понадобится, вернуть придётся именно FaceCheck.ID: поиска человека по лицу в
интернете у Face++ нет и не будет — это принципиально другой продукт.

Возврат недорог по коду: `base.py` не менялся, политика (согласие, кеш по хешу
содержимого, квота, cooldown) живёт в нём. Тело `_run` — загрузка снимка на
`https://facecheck.id/api/upload_pic`, затем опрос `/api/search` до появления
результата, с потолком по времени: зависший поиск обязан сдаться, а не морозить
разговор. Превью чужих лиц приходят в ответе как base64 и должны выбрасываться
ДО записи в кеш — иначе чужие лица оседают на диске на неделю.

Вернуть надо не только файл коннектора:

- `config/commands.yaml` — фраза «найди это лицо \*»;
- `johnny/actions/connector_action.py` — действие `face_search`;
- `johnny/connectors/factory.py` — строка в `BUILDERS` и проброс `testing`
  (пробная база: кредиты не списываются, но результат нельзя выдавать за
  настоящий — в ответе это должно быть сказано вслух);
- `config/secrets.yaml.example` — `facecheck_api_token`;
- `johnny/panel_tools.py` — карточка с кнопкой «Обзор».

Сторож — `tests/test_connector_actions.py::test_removed_phrases_are_gone_from_commands`:
падает, если `face_search` вернётся. Снимается тем же решением, которым
возвращается команда.

Возвращать ВМЕСТО Face++ не нужно, вопросы разные: FaceCheck не скажет, один ли
человек на двух снимках, Face++ не скажет, кто это. И к возврату применимо всё
из этого файла про приватность — там оно даже строже: поиск по интернету
означает, что снимок человека сопоставляется с публичными профилями, а это уже
не «сравнил два фото», а установление личности.
